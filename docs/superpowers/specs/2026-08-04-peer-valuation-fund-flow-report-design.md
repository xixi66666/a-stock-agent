# 同行估值与资金流报告增强设计

## 1. 背景与目标

当前项目已经从东方财富取得行业板块、同行批量行情、个股日级资金流和资本事件，并在东方财富资金流不可用时使用新浪日级资金流回退。现有报告仍缺少具名同行对比和订单级资金流细节，原因主要在确定性聚合与报告契约：同行记录在计算行业中位数后被丢弃，资金流仅稳定输出主力资金近 5 日和近 20 日累计。

本设计不新增外部数据源，目标是：

1. 在同一行业中确定性选择“市值接近 5 家 + 行业龙头 3 家”，去重后进入规范化快照。
2. 确定性计算最新日、近 5 日和近 20 日的主力、超大单、大单、中单、小单净流入。
3. 总体报告、研究报告、估值页面和资金页面使用同一份派生数据。
4. 模型只解释已经计算和校验的数据，不负责挑选同行或计算资金累计值。
5. 保留来源、状态、回退信息和局部失败边界，不制造替代值。

北向资金、行业资金流和龙虎榜席位级明细不在本次范围内，因为当前规范化数据链路尚未提供这些字段。

## 2. 方案选择

采用“确定性聚合后进入报告与页面”的方案。

- 不采用只修改提示词：原始数据虽然存在，但不同模型可能继续遗漏字段或自行选择样本，结果不可稳定复核。
- 不新建持久化分析子系统：当前需求可以在既有 Provider、快照和报告边界内完成，引入数据库和历史任务属于过度设计。
- Provider 层继续只负责取数和解析；分析层负责筛选、计算和状态传播；报告层负责结构化输出与叙述；页面只负责展示。

## 3. 数据源与既有边界

### 3.1 同行估值

继续使用东方财富板块和同行批量接口。同行原始记录已经包含：证券代码、证券名称、动态 PE、PB 和总市值。所有东方财富请求继续通过共享 `ProviderThrottle`，不得增加并行批量循环。

行业分类沿用现有 `IndustryValuationService` 选择的有效行业板块，并在输出中明确行业代码和行业名称。本次不使用模型纠正或猜测行业归属。

### 3.2 资金与筹码

继续使用：

- 东方财富日级资金流：主力、小单、中单、大单、超大单，最多 120 条历史记录；
- 新浪日级资金流回退；
- 东方财富资本数据：融资融券、大宗交易、股东户数、解禁、分红和龙虎榜汇总。

资金汇总只基于规范化 `FundFlow` 历史计算。融资、龙虎榜和大宗交易继续由既有资本分析逻辑确定性计算，不与订单级资金流混成同一数值。

## 4. 领域模型

### 4.1 同行选择原因

新增 `PeerSelectionReason` 枚举：

- `MARKET_CAP_NEARBY`：总市值最接近目标股票；
- `INDUSTRY_LEADER`：行业总市值领先。

序列化使用稳定枚举值，页面显示对应中文标签。一个同行可以同时具有两个原因。

### 4.2 同行比较记录

新增 `IndustryPeerComparison`：

- `code`、`name`；
- `peDynamic`、`pb`、`totalMarketValueYuan`；
- `targetPePremiumPercent`：目标股票相对该同行的 PE 溢价率；
- `targetPbPremiumPercent`：目标股票相对该同行的 PB 溢价率；
- `selectionReasons`：去重后的选择原因列表。

溢价率公式为 `(目标估值 / 同行估值 - 1) × 100`。目标值或同行值为空、零或负数时对应溢价率为 `null`，不得用零替代。

扩展 `IndustryValuationData`，在既有行业中位数、分位数和样本统计之外增加 `selectedPeers`。旧的行业汇总字段继续保留。

### 4.3 同行确定性筛选

目标股票不出现在同行列表中。筛选前只保留代码非空、代码不等于目标股票且总市值为正的记录。

1. 市值接近组：以目标股票总市值为基准，按绝对市值差升序、证券代码升序取前 5 家。
2. 行业龙头组：按总市值降序、证券代码升序取前 3 家。
3. 合并顺序先保留市值接近组，再追加尚未出现的行业龙头；重复证券合并选择原因。

如果目标股票在同行批次中缺少有效总市值，则市值接近组不可计算，只返回行业龙头组，并将分区标记为 `DEGRADED`，问题中明确写入目标市值缺失。如果行业有效市值样本不足，则返回实际可选数量，不从其他行业补齐。

### 4.4 资金流汇总

新增 `FundFlowWindowSummary`：

- `requestedDays`：请求窗口大小，分别为 1、5、20；
- `sampleDays`：实际参与计算的交易日数量；
- `mainNetYuan`、`superLargeNetYuan`、`largeNetYuan`、`mediumNetYuan`、`smallNetYuan`。

新增 `FundFlowSummary`：

- `latestDate`；
- `latestDay`；
- `fiveDay`；
- `twentyDay`。

新增纯计算组件 `FundFlowSummaryCalculator`。输入历史先按日期降序排列，同一日期只保留一条确定性记录，然后按窗口分别求和。`sampleDays` 反映窗口内实际参与的有效日期数量；如果窗口中任一日期缺少某个资金分类，该分类的窗口累计值为 `null`，不得跳过缺失日或用零补齐。

规范化快照新增 `DataSection<FundFlowSummary> fundFlowSummary`，同时保留原始 `fundFlow` 历史。派生分区继承原始资金流的状态和 `Provenance`：

- 东方财富成功时保持原状态；
- 新浪回退时保持 `DEGRADED` 和 `fallbackProvider`；
- 原始分区不可用时汇总分区也不可用；
- Provider 返回有来源但空历史时生成全空汇总，标记 `DEGRADED` 并记录“资金流为空成功”，与请求失败区分。

## 5. 数据流与职责

```text
Eastmoney / Sina Provider
        │
        ├── 行业板块 + 同行批量记录
        │          └── IndustryValuationCalculator
        │                    └── 行业统计 + 具名同行比较
        │
        └── 原始 FundFlow 历史
                   └── FundFlowSummaryCalculator
                              └── 1/5/20 日分类汇总
                                      │
                              StockResearchSnapshot
                       ┌──────────────┼──────────────┐
                       │              │              │
                 总体报告         研究报告       REST / UI 页面
```

Provider 不做同行筛选或累计计算。模型不接触外部接口，也不调用新的工具。所有排序、去重、金额累计、溢价率和状态选择都在模型之外完成。

## 6. 报告契约

### 6.1 总体报告

`OverallReportDraft` 的模型叙述字段保持兼容，不要求模型返回新的计算字段。`OverallResearchReport` 增加：

- `industryValuation`：包含行业统计和具名同行比较；
- `fundFlowSummary`：包含最新日、5 日和 20 日分类汇总。

这两个字段由 `OverallReportService` 从生成时使用的同一份快照复制，不接受模型自报数值。现有 `valuationAndIndustry` 与 `technicalAndCapital` 继续作为模型解释文字。总体报告校验器继续验证叙述中出现的数字必须存在于快照。

### 6.2 研究报告

扩展报告子结构：

- `ValuationIndustryAnalysis` 增加规范化行业估值数据；
- `TechnicalAndFlowAnalysis` 增加规范化资金流汇总。

`InstitutionalReportComposer` 继续生成现有事实列表，并补充同行选择、估值溢价和分类资金累计事实。确定性回退报告和模型辅助报告必须具有相同的结构化数据。

### 6.3 API 兼容性

现有接口地址和请求体不变。响应只增加字段，不删除或重命名现有字段。旧前端忽略新增字段时仍能工作。

## 7. 页面设计

### 7.1 估值页面

保留现有个股 PE、PB 和总市值指标。新增同行估值表：

- 目标股票固定为首行并标记“目标”；
- 同行列为代码、名称、筛选标签、动态 PE、PB、总市值、目标相对 PE 溢价、目标相对 PB 溢价；
- 缺失值显示 `--`，不得显示为零；
- 小屏幕使用已有横向表格容器，不压缩到不可读宽度。

### 7.2 资金页面

保留最新日资金指标卡，将中单和小单分别展示，不再只合并为“中小单”。新增 5 日和 20 日分类汇总表，列出主力、超大单、大单、中单、小单和实际样本天数。

融资融券、大宗交易、股东户数和解禁区块保留。研究报告中的龙虎榜、大宗和融资确定性证据不要求在本次资金汇总表重复为订单资金。

### 7.3 报告页面

总体报告增加“同行估值对比”和“资金流明细”两个确定性区块，显示在对应模型叙述之后。研究报告在“估值与行业”和“技术与资金”模块中显示相同结构化表格。

两类报告的模型名称、来源引用、诊断和免责声明保持不变。结构化区块不可被模型失败清空；当对应数据分区不可用时显示状态和原因。

## 8. 错误、质量与安全

- 同行样本不足允许少于 8 家，显示实际样本数。
- 非正 PE/PB 不参与行业统计和溢价计算，但具名同行仍可因有效市值被选中，其估值显示为不可用。
- 同行数据失败只使行业估值分区不可用，不影响核心行情、K 线和其他报告分区。
- 资金历史少于 5 日或 20 日时按实际记录汇总并暴露 `sampleDays`。
- 资金数据失败不影响行业估值、基本面和事件章节。
- 所有新增响应只含公开市场数据和安全来源元数据，不包含请求头、Cookie、Token、API Key 或私有连接配置。
- 不新增任意 URL、文件、Shell 或不受限 HTTP 能力给 Spring AI 工具。

## 9. 测试设计

所有行为变更使用红—绿—重构，默认测试保持离线。

### 9.1 同行估值

- 市值接近组按绝对市值差和代码稳定排序；
- 行业龙头组按市值和代码稳定排序；
- 两组去重并合并双标签；
- 目标股票被排除；
- 无效市值被排除；
- 无效 PE/PB 不计算溢价；
- 目标市值缺失时只返回龙头并传播降级问题；
- 样本不足时不跨行业补齐；
- Provider 解析和 `Provenance` 保持现有契约。

### 9.2 资金流汇总

- 输入乱序时按日期降序计算；
- 最新日、5 日和 20 日五类资金累计正确；
- 少于窗口长度时 `sampleDays` 正确；
- 重复日期确定性去重；
- 字段缺失不伪造成零；
- 新浪回退的 `DEGRADED` 和来源信息传播到汇总；
- 空成功与 Provider 失败具有不同问题描述。

### 9.3 报告与 UI

- 总体报告结构化字段来自快照而非模型草稿；
- 确定性研究报告和模型辅助研究报告包含相同的同行与资金汇总；
- 估值页目标行、同行标签和缺失值正确；
- 资金页最新日、5 日和 20 日数据正确；
- 两类报告渲染结构化表格，并在分区不可用时保留其他报告内容；
- 在 `1440x1000`、`1024x768`、`768x1024`、`390x844` 检查表格滚动、文字适配、水平页面溢出和固定头部遮挡。

## 10. 验收标准

1. 同行业估值展示目标股票、市值接近 5 家和行业龙头 3 家，重复证券合并标签。
2. 同行选择、估值统计和溢价率全部由后端确定性计算。
3. 资金流展示最新日、近 5 日和近 20 日的五类净流入及实际样本天数。
4. 总体报告、研究报告、估值页面和资金页面使用同一份规范化派生数据。
5. 模型失败不删除确定性同行或资金明细；数据源局部失败不阻断其他报告章节。
6. 响应保持向后兼容，并保留数据状态、来源和回退信息。
7. 不新增外部数据源，不扩大模型工具安全边界。
8. 离线 Java 测试、打包和 UI 自动化测试通过；实时数据验证继续单独运行。

## 11. 后续范围

如果后续需要北向资金、行业资金流或龙虎榜席位级明细，应分别新增规范化 Provider 契约和独立设计，不在本次实现中通过模型猜测或复用不相干字段。
