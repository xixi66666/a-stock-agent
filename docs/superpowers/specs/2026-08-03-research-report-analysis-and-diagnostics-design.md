# 研究报告深度分析与模型错误诊断设计

## 1. 背景

当前机构研究报告存在三个相互关联的问题：

1. 模型调用、结构化响应解析等异常被统一转换为 `model unavailable`，无法判断真实失败原因。
2. “核心驱动”直接展示规则维度的内部摘要，例如“规则方向分100”或“PE/PB与行业中位数比较”，不是针对当前证券提炼的分析结论。
3. 各模块只输出少量指标和一句方向描述，缺少判断过程、理论依据、反证条件及证据引用；模型收到的证据包也没有足够的结构化事实支撑深入叙述。

本设计采用“确定性分析主导、模型辅助叙述”的方案。模型不可用时，规则报告仍须完整、可读和可追溯；模型可用时，只能在确定性结论和证据边界内组织语言。

## 2. 目标与非目标

### 2.1 目标

- 每个分析模块输出事实、信号、结论、方法依据、反证、限制和来源。
- “核心驱动”只展示由本次数据计算出的具体结论，不暴露内部规则分。
- 模型获得足够但有界的结构化证据，能够写出有事实和理论支持的叙述。
- 模型失败时仍返回完整的确定性研究报告。
- API 和页面提供可排查的结构化错误报告；本地日志保留完整异常链和堆栈。
- 所有错误信息经过脱敏，不泄露密钥、认证头、Cookie、私有请求参数或完整本地配置。
- 保持 `Provenance` 从数据分区到事实、信号、报告和页面的可追溯关系。

### 2.2 非目标

- 不让模型修改确定性方向、分数、证据状态或来源。
- 不允许模型补充证据包之外的数字和事实。
- 不增加任意 URL、文件、Shell 或无限制 HTTP 模型工具。
- 不输出买卖指令、目标仓位、收益保证或个性化投资建议。
- 本次不修改行情、K 线和外部数据 Provider 的选源规则。

## 3. 总体架构

报告生成链路调整为：

```text
StockResearchSnapshot
  -> 确定性模块分析器
  -> ModuleAnalysis 集合
  -> 综合判断与核心驱动排序
  -> ReportEvidencePackage
  -> 模型叙述（可选）
  -> 叙述校验
  -> InstitutionalResearchReport
```

异常链路为：

```text
模型配置 / 请求 / 响应解析 / 叙述校验 / 报告组装
  -> ModelFailureClassifier
  -> 脱敏 ModelDiagnostic
  -> 确定性报告 + 页面诊断信息
  -> 完整异常写入本地日志
```

确定性模块分析器是分析结论的唯一所有者。模型叙述是可选增强，不参与方向计算，也不能覆盖冲突、缺失数据、失效条件和来源。

## 4. 模块分析契约

### 4.1 统一结构

新增统一的模块分析记录，至少包含：

| 字段 | 含义 |
| --- | --- |
| `module` | 模块枚举，避免用展示文本参与逻辑 |
| `conclusion` | 本次数据对应的模块结论 |
| `direction` | 偏强、偏弱、中性或证据不足 |
| `confidence` | 由覆盖度、时效性和冲突计算的确定性置信等级 |
| `facts` | 带单位、观察时间和证据 ID 的结构化事实 |
| `signals` | 规则命中结果及其方向和影响程度 |
| `methodology` | 使用的金融或统计方法及适用条件 |
| `counterEvidence` | 与主结论相反或削弱结论的证据 |
| `limitations` | 样本、时效、缺失项和不可比性限制 |
| `sourceIds` | 所依赖的证据和来源 ID |

内部原始分数仅用于排序和聚合，不作为报告正文或核心驱动的展示字段。

### 4.2 技术与量价

至少覆盖：

- 趋势：收盘价与 SMA20/SMA60 的位置、均线排列及趋势失效条件。
- 动量：MACD、RSI 和阶段收益，说明趋势与动量是否互相确认。
- 量价：量比、成交额或换手率变化，区分放量确认与量价背离。
- 风险：波动率、最大回撤和样本长度；历史不足时不得给出专业级结论。

理论依据说明趋势跟随、动量确认、量价确认及均值回归的适用边界。单一指标不得独立形成模块结论。

### 4.3 资金与筹码

至少覆盖：

- 近 5 日和近 20 日主力净流向及方向一致性。
- 融资余额变化、大宗交易、龙虎榜、股东人数、解禁和分红等可用结构化数据。
- 短周期资金与中周期筹码是否冲突。

理论依据说明资金流仅代表已发生交易，不能单独证明未来方向；大宗交易、融资和股东人数必须结合时间、规模和可用样本解释。

### 4.4 基本面与机构预期

至少覆盖：

- 收入、归母净利润、经营现金流及可用盈利质量指标的同比变化。
- EPS 一致预期、覆盖机构数、评级分布和预测分歧。
- 实际经营趋势与机构预期是否一致。

理论依据说明增长质量、现金流验证、盈利持续性和预期差。机构覆盖不足时降低预期信号置信度，不用缺失数据推断一致预期。

### 4.5 公告与结构化事件

对公告和资本事件分别分类，再进行联合判断：

- 明确事件类型、发生或披露时间、影响方向、有效期和来源。
- 区分已发生事实、管理层计划和市场解读。
- 同时保留正向催化、负向风险和相互冲突的事件。

不再使用“公告和资本事件共同判断”作为结论。无可评价事件时明确写“当前窗口没有足够的结构化事件证据”。

### 4.6 行业估值

至少覆盖：

- 个股 PE/PB、行业中位数、有效样本数和溢价或折价比例。
- PE 无意义或样本不可比时，明确降级到 PB 或证据不足。
- 估值结论与基本面增长、盈利质量相互验证。

理论依据说明相对估值的可比性约束。低估值不是独立正向驱动，高估值也不等同于确定性负向结论。

## 5. 核心驱动

核心驱动从各模块的 `signals` 中选择，不再直接复用维度证据摘要。

每条核心驱动包含：

- 具体结论，例如“收盘价位于 SMA20 和 SMA60 上方，20 日收益为正，趋势与动量互相确认”。
- 方向和影响等级。
- 支撑该结论的事实与证据 ID。
- 为什么会影响综合方向的简短解释。
- 对应反证或失效条件。

排序使用内部的加权影响绝对值、证据质量、时效性和冲突折扣。页面不展示原始规则分。正向和负向证据均可进入核心驱动，避免只选取支持最终方向的内容。

## 6. 模型证据包与叙述

`ReportEvidencePackage` 增加模块分析结果、结构化事实、方法依据和核心驱动，不再只提供“该分区已提供可追溯数据”一类占位摘要。

模型输出仍是受限的 `ReportNarrativeDraft`，但各模块叙述必须：

- 引用实际存在的证据 ID。
- 解释至少一个主要信号及其金融或统计依据。
- 在存在反证时明确保留反证。
- 不添加证据包外的数字、日期、来源和事件。
- 不改变确定性方向、证据状态、核心驱动和失效条件。

模型返回空字段时仅回退该叙述字段，不丢弃其他已通过校验的模块；出现全局安全或结构错误时，整份模型叙述回退为确定性叙述。

## 7. 真实错误报告

### 7.1 失败阶段

模型相关失败必须分类为：

| 阶段 | 示例错误码 |
| --- | --- |
| `CONFIGURATION` | `MODEL_CONFIGURATION_INVALID` |
| `REQUEST` | `MODEL_TIMEOUT`、`MODEL_CONNECTION_FAILED`、`MODEL_HTTP_ERROR` |
| `RESPONSE_MAPPING` | `MODEL_EMPTY_RESPONSE`、`MODEL_RESPONSE_PARSE_FAILED` |
| `VALIDATION` | `MODEL_NARRATIVE_VALIDATION_FAILED` |
| `ASSEMBLY` | `REPORT_ASSEMBLY_FAILED` |

不得再用一个 `catch (Exception)` 将所有情况统一写成 `model unavailable`。

### 7.2 API 诊断对象

报告增加可选的 `modelDiagnostic`：

```json
{
  "failureStage": "VALIDATION",
  "errorCode": "MODEL_NARRATIVE_VALIDATION_FAILED",
  "exceptionType": "ReportValidationException",
  "message": "模型叙述包含证据包未支持的数字",
  "validationIssues": ["UNSUPPORTED_NUMBER"],
  "modelName": "configured-chat-model",
  "durationMs": 1832,
  "occurredAt": "2026-08-03T01:30:00Z",
  "traceId": "agent-..."
}
```

`message` 是真实根因的安全摘要，不是固定占位文本。HTTP 状态、响应体摘要等上游信息只在确认脱敏后写入本地日志；API 不返回上游原始响应体。

### 7.3 日志与脱敏

- 使用参数化日志记录失败阶段、错误码、模型名、耗时和 `traceId`。
- 本地日志保留完整异常类型、因果链和堆栈帧；每一层异常消息必须先脱敏，不能直接记录未经审查的原始异常对象。
- 对字段名包含 `key`、`token`、`secret`、`authorization`、`cookie` 的内容进行删除或替换。
- URL 查询参数先经过共享脱敏器；不得记录完整模型请求、Authorization 头或本地配置。
- 脱敏不得把错误压缩成通用占位语；HTTP 状态、异常类型、失败阶段和不含敏感值的根因文本必须保留。
- 校验失败记录全部校验码，但不重复记录可能含敏感内容的整份模型原文。

### 7.4 页面呈现

模型失败时页面继续展示完整确定性报告，并显示“模型叙述回退”状态。诊断区域展示失败阶段、错误码、安全消息、时间、耗时、模型名和 `traceId`。校验失败时展示校验问题的中文解释。

诊断区域默认紧凑展示，详情可展开；不得用颜色作为唯一状态表达。页面不展示完整 Java 堆栈，以避免泄露内部路径和配置，完整堆栈由本地日志提供。

## 8. 数据状态和局部降级

- 空成功、Provider 失败、陈旧数据、未验证数据和不可用数据继续保持不同状态。
- 单个分析模块缺失时，只降级该模块；核心行情和 K 线均不可用时才判定整份报告不可用。
- 模型叙述失败不改变确定性报告的方向和证据状态。
- 模型某个模块字段为空时只回退该字段；未知证据、交易指令或无法解析的结构化响应触发模型叙述整体回退。
- 所有事实、信号和核心驱动必须能够追溯到 `Provenance`。

## 9. 前后端契约

现有 `InstitutionalResearchReport` 保持主要字段兼容，并扩充：

- 各模块增加 `conclusion`、`facts`、`signals`、`methodology`、`counterEvidence` 和 `limitations`。
- `coreDrivers` 改为具体驱动对象，不再使用通用 `ReportEvidence` 占位文本。
- 增加可选 `modelDiagnostic`。
- 保留 `generationMode`，用于区分模型辅助、确定性回退和报告不可用。
- 保留来源、抓取时间、规则版本、提示词版本和免责声明。

前端按照统一模块结构渲染，不在 JavaScript 中重新计算投资判断。

## 10. 测试与验收

所有行为变更使用红-绿-重构流程。

### 10.1 单元测试

- 每个模块在正向、负向、中性、冲突和数据不足条件下输出正确结构。
- 核心驱动包含实际事实和解释，不包含“规则方向分”或通用占位语。
- 相对估值处理负 PE、空样本、样本不足和异常值。
- 资金与筹码不会因只有记录条数而形成方向结论。
- 模型超时、连接失败、HTTP 错误、空响应、解析失败和校验失败分别生成正确诊断码。
- 脱敏器删除密钥、认证头、Cookie 和敏感查询参数。
- 模型失败后确定性报告内容保持完整。

### 10.2 集成测试

- Mock 模型分别返回合法结构、非法 JSON、未知证据、无依据数字和交易指令。
- API 保持兼容，并在回退报告中返回 `modelDiagnostic`。
- 日志包含 `traceId` 和真实异常类型，不包含测试凭据。
- 默认 Maven 测试不访问外部数据源；外部测试继续使用 `external` 标签。

### 10.3 UI 测试

- 核心驱动展示具体结论、依据和失效条件。
- 每个模块展示方法依据、反证和数据限制。
- 错误诊断能够展开，并包含错误码和 `traceId`。
- 在 1440x1000、1024x768、768x1024 和 390x844 下无横向溢出、按钮文字溢出和固定头部遮挡。
- 模型失败状态下仍能阅读全部确定性报告。

### 10.4 完成验证

完成实现后执行：

```powershell
.\mvnw.cmd '-Dmaven.repo.local=.m2/repository' clean test
.\mvnw.cmd '-Dmaven.repo.local=.m2/repository' '-DskipTests' package
.\scripts\verify-data.cmd
npm.cmd run test:ui
git diff --check
```

还需检查生成的真实报告、模型失败日志、诊断区域截图和敏感信息审计结果，不能只依赖退出码。

## 11. 兼容与迁移

- 先增加新字段并保留现有构造兼容入口，避免一次性破坏 Controller 和测试夹具。
- 前端同时容忍旧版报告和新版模块结构，待后端稳定后再移除兼容分支。
- 规则版本和提示词版本升级，以便区分新旧报告。
- 工作区现有的事实列表改动作为输入保留，在实施阶段迁移进统一模块分析结构，不回退已有功能。
