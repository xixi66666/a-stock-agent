# QuantResearchReport v2 设计

## 1. 目标

将 Agent 分析中的“生成研究报告”升级为面向单只 A 股的专业量化研究报告。报告参考私募基金和券商量化研究报告的组织方式，但只输出当前数据源能够真实支持的内容。

报告以客观指标、来源和限制为事实底座，以纯文字研究叙述为主要呈现形式。报告不生成综合评分、因子评分、置信分、排名或任何其他主观打分。

## 2. 范围

### 2.1 本阶段包含

- 新建 `QuantResearchReport` v2 契约。
- 新增 `POST /api/agent/quant-report` 接口。
- 保留 `POST /api/agent/analyze` 及旧 `InstitutionalResearchReport`，避免破坏已有客户端。
- 复用现有单股快照、技术指标、财务、估值、资金流、资本事件、新闻和公告数据。
- 增加基准指数数据边界，优先复用现有行情适配链路并用契约测试验证实际可用性。
- 计算可复核的收益、波动、回撤、风险和相对基准指标。
- 由 Java 生成事实包，由可选大模型生成受限中文段落。
- 在模型异常、数据缺失或模型输出校验失败时提供确定性文字回退。

### 2.2 本阶段不包含

- 组合净值、持仓流水、交易流水或真实策略回测。
- Barra 风险模型、全市场横截面因子暴露或 Brinson 归因。
- 私募基金的申赎、费率、审计信息或 LP 专属披露。
- 买入、卖出、加仓、减仓、目标价或个性化投资建议。

没有真实数据的组合级字段必须返回结构化不可用状态，不能使用文字或模型补造。

## 3. 架构与迁移

```text
POST /api/agent/quant-report
        |
        v
QuantResearchReportService
        |
        +-- StockResearchSnapshot
        +-- BenchmarkDataGateway
        +-- QuantFactsCalculator
        +-- QuantReportComposer
        +-- optional QuantNarrativeGenerator
        |
        v
QuantResearchReport
```

旧接口继续使用现有 `StockAnalysisAgent` 和 `InstitutionalResearchReport`。新接口使用独立的 v2 DTO 和服务，不让旧总体报告接口、旧研究报告接口和新报告互相覆盖。

模型配置继续复用 `institutional-report` 角色，避免增加一套 API Key 或模型目录。新报告不使用动态工具调用；模型只接收 Java 生成的有界事实包。

## 4. 报告契约

`QuantResearchReport` 按机构研究报告的阅读顺序组织：

```text
reportMeta
marketContext
securityOverview
factorObservations
signalNarrative
riskNarrative
forwardView
portfolioScope
sourceReferences
```

### 4.1 元数据

必须包含证券、报告类型、报告周期、观察截止时间、生成时间、数据质量、可用分区、规则版本、提示词版本和免责声明。

### 4.2 市场环境与基准

包含沪深 300、中证 500、中证 1000（数据可用时）的区间收益、个股相对收益、相关性、Beta 和 Information Ratio。基准数据缺失、日期无法对齐或样本不足时，返回 `UNAVAILABLE` 及原因。

市场风格只在存在可验证的指数或横截面数据时描述；不使用目标股票的行业归属替代市场风格表现。

### 4.3 个股与因子观察

包含价格行为、收益窗口、估值、基本面、资金和事件的文字观察。因子名称可以使用动量、价值、成长/质量、波动、流动性和资金情绪，但字段表示为事实和文字倾向，不包含分数、排名或综合权重。

### 4.4 风险与前瞻

包含历史波动率、下行波动率、最大回撤、历史 VaR/CVaR、偏度、峰度、流动性风险、事件风险和明确的失效条件。前瞻部分只能说明市场环境、因子适应性、需要观察的条件和强弱情景，不得转化为交易指令。

### 4.5 组合范围

固定标记 `scope = SINGLE_SECURITY`。持仓、策略净值、组合换手率、集中度、对冲比例和组合绩效等字段使用 `UNAVAILABLE`，原因写明“当前系统没有组合净值和交易流水”。

## 5. 数据源能力

现有 Provider 可以支持单股报告的行情、日 K、技术指标、个股估值、行业同行估值、财务同比、资金流、资本事件、研究、新闻和公告。腾讯主行情与复权日 K、百度 K 线交叉校验、东方财富扩展数据、新浪财务与资金流备源、巨潮公告的来源和降级状态必须继续保留。

当前没有独立的基准指数快照、市场风格时间序列、股票池横截面因子、组合持仓、交易流水或净值曲线。因此，v2 不得声称已经具备组合级绩效分析或 Barra/Brinson 能力。

新增 `BenchmarkId` 和 `BenchmarkDataGateway`，不把指数强行复用为普通 `SecurityId`。优先尝试现有腾讯行情适配链路，显式维护指数代码映射；每个指数都需要解析、身份、OHLC、日期排序和最小历史长度契约测试。

## 6. 确定性计算规则

### 6.1 标准指标

以下指标使用行业通用定义，并在报告方法区显示公式、窗口、年化因子、无风险利率假设和样本长度：

- 区间收益：`P_t / P_(t-n) - 1`。
- 年化波动率：日收益标准差乘以 `sqrt(252)`；现有 250 年化实现需要在 v2 中显式记录参数。
- Sharpe：年化超额收益除以年化波动率；第一版无风险利率默认按 0，并明确披露。
- Sortino：年化超额收益除以下行收益波动率。
- 最大回撤：价格或净值相对历史峰值的最深跌幅，并记录起止日期。
- Calmar：年化收益除以最大回撤绝对值。
- 历史 VaR/CVaR：按历史收益分布计算 95% 分位和尾部均值，样本不足时不可用。
- Beta：个股和基准同步收益的协方差除以基准收益方差。
- Information Ratio：主动收益均值除以主动收益波动率并年化。
- 胜率和盈亏比：按明确定义的日收益或持有窗口收益计算，不混用交易策略口径。

### 6.2 项目研究观察

动量、价值、成长/质量、波动、流动性和资金情绪是通用因子家族，但单股数据不足以计算严格的横截面暴露。报告只输出“动量近期改善”“估值低于行业中位数”“流动性约束上升”等证据化文字，并列出原始指标、窗口、来源和限制。

现有研究判断引擎中的五维权重只属于旧报告的项目规则。v2 不复用这些权重，不产生总分，也不把规则阈值包装为行业标准模型。

## 7. 大模型叙述与校验

事实层与叙述层分离：

```text
QuantReportFacts       Java 事实、指标、来源、限制、不可用状态
QuantNarrativeDraft    模型生成的受限文字段落
QuantResearchReport    Java 合并并校验后的最终报告
```

模型只能输出摘要、市场环境、价格行为、因子观察、估值基本面、资金事件、风险失效条件和前瞻展望等文字段落。模型不得新增事实、数字、日期、来源、分数或交易动作。

校验器必须检查：

- 文本数字是否可在事实包中找到。
- 是否出现交易指令、目标价、收益保证或个性化建议。
- 是否出现综合得分、因子分数、置信度、排名等禁用打分内容。
- 是否把 `UNAVAILABLE` 分区写成具体数字或确定结论。
- 是否保留冲突、缺失数据、数据时点、来源和方法限制。

校验失败时只回退对应段落；模型整体异常时返回完整的确定性文字报告，并附局部诊断，不把异常堆栈暴露给浏览器。

## 8. 前端呈现

新报告页面采用浅色、紧凑、研究工作台风格：

1. 标题、证券、报告周期、数据截止时间和生成时间。
2. 数据质量与不可用分区说明。
3. 执行摘要。
4. 市场环境与基准表现。
5. 个股收益与价格行为。
6. 因子观察，使用文字和紧凑事实表，不使用评分仪表盘。
7. 估值与基本面。
8. 资金、事件与情绪。
9. 风险与失效条件。
10. 前瞻展望。
11. 组合级信息不可用说明。
12. 来源、方法和免责声明。

数值必须显示单位、窗口和观察时间；`UNAVAILABLE`、`STALE` 和 `DEGRADED` 必须显示状态文字与原因，不能渲染为 0、空白或彩色暗示。页面不增加营销文案、分数、雷达图或装饰性模块。

## 9. 测试与验收

- 为每个标准指标添加带已知结果的离线单元测试，覆盖样本不足、零方差、日期错位、空值和异常收益。
- 为基准适配器添加身份、OHLC、排序、历史长度和不可用状态测试。
- 为事实包和报告组装器添加“无分数字段”和“组合级不可用不伪造”测试。
- 为叙述校验器添加编造数字、交易指令、打分词和覆盖不可用数据的失败测试。
- 为新 Controller 添加成功、基准不可用、模型未配置和模型失败测试；确认旧 Controller 测试继续通过。
- UI 使用 Playwright 验证 1440x1000、1024x768、768x1024 和 390x844，检查无横向溢出、固定头部遮挡、长文本换行和状态可读性。
- 默认 Maven 测试保持离线；外部 Provider 测试继续标记为 `external`。

## 10. 验收标准

实现完成后，用户可以通过新接口获得一份不含任何打分的单股量化研究报告。报告中的每个数字都能追溯到快照字段、计算公式、观察时间和来源；不能支持的基准、组合或策略指标明确显示不可用；模型不可用时报告仍能返回确定性文字内容；旧研究报告和总体报告接口保持兼容。
