# 总体报告可选择模型设计

## 1. 背景

总体报告当前通过 `overall-report` 角色固定取得一个模型，页面文案和按钮又直接写成 DeepSeek。这与现有 `app.ai.models` 多命名模型配置不一致：OpenAI 兼容模型虽然能同时注册，但用户无法在生成总体报告时选择具体模型。

本次重构把总体报告从“固定 DeepSeek 功能”改为“从后端可用模型目录中选择一个模型生成报告”。现有机构研报链路、总体报告数据结构、确定性校验和局部失败边界保持不变。

## 2. 目标与非目标

### 2.1 目标

- 页面只展示已启用且配置完整的命名模型。
- 用户生成总体报告前可以选择模型。
- 前端模型列表来自后端，不写死 `primary`、`deepseek` 或 `mimo`。
- 未显式选择模型时，继续使用 `app.ai.roles.overall-report` 指定的默认模型，兼容现有请求。
- 后端只接受已注册的模型 ID，不接受客户端传入 URL、API Key 或任意模型连接参数。
- 报告和诊断保留实际模型名，页面不再把总体报告固定称为 DeepSeek 报告。

### 2.2 非目标

- 不提供浏览器端 API Key、Base URL、模型参数编辑功能。
- 不实现运行时修改配置、热加载、负载均衡或自动故障转移。
- 不改变总体报告提示词、结构化输出、验证规则或安全边界。
- 不改变机构研报的模型选择方式。

## 3. 架构

### 3.1 可用模型目录

`NamedChatClientRegistry` 是可调用模型的唯一来源。它提供：

- 按模型 ID 查找已注册模型；
- 列出可用于总体报告的已注册模型；
- 解析 `overall-report` 角色对应的默认模型 ID。

目录响应只包含：

- `id`：配置中的命名模型 ID；
- `modelName`：实际模型名称；
- `defaultModel`：是否为总体报告默认模型。

响应不得包含 API Key、Base URL、Authorization、连接路径或其他本地配置。

### 3.2 API

新增模型目录接口：

```http
GET /api/agent/models?capability=overall-report
```

示例响应：

```json
{
  "models": [
    { "id": "primary", "modelName": "gpt-5", "defaultModel": false },
    { "id": "deepseek", "modelName": "deepseek-v4-flash", "defaultModel": true },
    { "id": "mimo", "modelName": "mimo-v2.5-pro", "defaultModel": false }
  ]
}
```

总体报告接口保持地址不变，请求增加可选字段：

```http
POST /api/agent/overall-report
Content-Type: application/json

{ "code": "600519", "modelId": "mimo" }
```

没有 `modelId` 时按 `overall-report` 角色解析默认模型。显式 `modelId` 不存在或不可用时返回 `400 Bad Request`，不得静默换成其他模型。

### 3.3 总体报告服务

`OverallReportService` 不再持有启动时固定创建的 DeepSeek 生成器。服务在每次请求中先解析模型选择，再为选中的 `NamedModel` 构造 `SpringAiOverallReportGenerator`，随后复用现有快照获取、模型生成、校验、一次修复和诊断流程。

模型选择和报告生成职责分开：注册表负责安全解析命名模型，服务负责总体报告工作流。请求始终只能引用服务端已注册 ID，不能扩大 Spring AI 工具或网络访问边界。

## 4. 前端交互

进入 Agent 页面后，前端加载总体报告可用模型目录，并在生成按钮上方渲染紧凑的原生选择框。选项显示 `模型 ID · 实际模型名`，默认选中目录中 `defaultModel=true` 的项目；若不存在默认项，则选中首个可用模型。

点击“生成总体报告”时，请求体携带当前 `modelId`。股票切换期间继续使用现有加载代次标识丢弃过期响应，模型选择在当前页面会话内保持不变。

页面中的以下固定 DeepSeek 文案改为通用表达：

- 按钮副标题显示当前选择的实际模型名；
- 等待提示说明“所选模型将读取当前股票的完整规范化快照”；
- 报告标题显示“总体报告”；
- 报告元数据继续显示服务端返回的实际 `modelName`。

界面继续使用项目既有语义色、紧凑布局和原生可访问控件，不增加装饰性卡片或新的视觉体系。

## 5. 状态与错误处理

- 模型目录为空：禁用生成按钮和选择框，显示“没有可用模型，请检查本地配置”。
- 模型目录加载失败：只影响总体报告控制区，现有机构研报和研究快照继续可用。
- 未传模型 ID：使用总体报告默认模型；默认模型不存在时返回现有未配置状态。
- 未知或不可用模型 ID：返回 `400` Problem Details，消息明确指出请求模型不可用。
- 模型超时、认证失败、HTTP 错误、解析失败和校验警告：沿用现有局部诊断，诊断记录实际模型名。
- 任一模型失败都不清空其他模型此前生成的报告，也不影响机构研报。

## 6. 兼容性

已有 `{ "code": "600519" }` 请求仍然有效，并使用 `overall-report` 默认角色。总体报告响应结构保持不变。新增模型目录是只读接口，不触发模型网络调用。

模型选择是启动时配置的运行期引用；修改模型配置或角色映射后仍需重启应用。

## 7. 测试设计

所有行为变更按红—绿—重构执行，默认测试保持离线。

### 7.1 后端

- 注册表只列出已成功注册的模型，并正确标记总体报告默认模型。
- 注册表可以按显式模型 ID 返回相互独立的客户端。
- 总体报告服务使用请求指定的模型生成报告。
- 未传模型 ID 时使用默认角色模型。
- 未知或不可用模型 ID 被拒绝，且不会获取股票快照或调用其他模型。
- 模型目录响应不包含 URL、Key 或连接参数。
- 原有无 `modelId` Controller 测试继续通过。

### 7.2 前端

- 页面根据模型目录动态生成选择项并选中默认模型。
- 生成请求体包含当前选择的 `modelId`。
- 模型目录为空时禁用生成按钮并显示配置提示。
- 模型目录失败不影响机构研报按钮。
- 总体报告标题、等待文案和按钮不再写死 DeepSeek。
- 切换股票时忽略过期总体报告响应，模型选择保持不变。

### 7.3 验证

- 运行聚焦 Java 单元和 Web 测试。
- 运行默认离线 Java 测试与打包。
- 运行 UI 自动化测试。
- 在 `1440x1000`、`1024x768`、`768x1024`、`390x844` 检查选择器文字、按钮适配、水平溢出和固定头部遮挡。
- 检查 `git diff --check` 和敏感信息审计，不读取或输出真实 API Key。

## 8. 验收标准

1. 总体报告区域展示后端返回的全部可用命名模型，并允许用户选择。
2. 生成请求只提交证券代码和模型 ID，后端严格按已注册模型路由。
3. 未传模型 ID 的旧请求继续走 `overall-report` 默认模型。
4. 未知模型不会触发快照获取、模型调用或隐式降级。
5. 页面和错误提示不再把总体报告固定为 DeepSeek。
6. 模型目录和报告响应不暴露密钥、Base URL 或私有连接配置。
7. 机构研报、总体报告校验和局部失败行为保持不变。
8. 默认 Java 与 UI 测试保持离线，相关测试和构建验证通过。
